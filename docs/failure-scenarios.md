# Сценарии отказов

| Сбой | Как воспроизвести | Ожидаемый результат |
| --- | --- | --- |
| API остановлен после загрузки | Остановить API в запущенном [демо](demo.md) | SDK оставляет последнюю ревизию и продолжает оценку локально. |
| SDK запущен при недоступном API | Перезапустить демо после остановки API | Для обеих оценок действует переданный `fallback: false`. |
| Callback диагностики выбросил исключение | `dotnet test --filter FullyQualifiedName~ThrowingFailureObserver` | После `503` SDK выполняет следующую попытку, принимает снимок и штатно завершает обновление при освобождении клиента. |
| Сервер прислал заголовки и завис на теле ответа | `dotnet test --filter FullyQualifiedName~RequestDeadlineAndRefreshTicks` | По истечении управляемого тайм-аута SDK сохраняет текущий снимок. На следующем тике он принимает новую ревизию. |
| Снимок не дочитан, битый JSON или неизвестная схема | `dotnet test --filter FullyQualifiedName~FailedRefreshesKeepLastSnapshot` | Действующая ревизия сохраняется. Следующий корректный снимок активируется. |
| Обновление во время локальной оценки | `dotnet test --filter FullyQualifiedName~ConcurrentEvaluations` | Результат и номер ревизии всегда принадлежат одному снимку. |
| Конкурирующие публикации | `dotnet test --filter FullyQualifiedName~ConcurrentWriters` | Из десяти запросов с одной ожидаемой ревизией только один получает `201`. Остальные получают `409`. В аудите одна запись об этой публикации. |
| Ошибка вставки после изменения указателя ревизии | `dotnet test --filter FullyQualifiedName~RejectedInsert` | Ограничение PostgreSQL отклоняет вставку. Транзакция откатывается, и ту же ревизию можно опубликовать повторно. |

Если клиент потерял ответ на публикацию, прочитайте текущую конфигурацию или историю и сверяйте содержимое. Повтор с устаревшей ревизией вернёт `409`.
